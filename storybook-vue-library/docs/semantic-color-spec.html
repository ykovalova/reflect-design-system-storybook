Reflect Semantic Color Spec

Six groups named after the property they paint, one naming rule, and a second collection that lets an icon work out its own colour. This is the rationale; the token-by-token lookup lives in semantic-token-map.md.

Naming

The group is a property, not a meaning

Group/Role/Rank/State
GroupWhat property you're painting. Six, fixed: Background, Border, Text, Icon, Overlay, Brand/Logo.
RoleWhich slot. A neutral rung, a status family, or Action for something pressable.
RankOnly under Action. Primary · Secondary · Tertiary · Danger · DangerTertiary · Control.
StateOptional, always last. Hover · Pressed · Selected · Disabled. Absent means rest.

A static ground and a pressable fill are both Background. What separates them is the Action role, one level in. There is no Surface group any more — a card is Background/Raised, a button face is Background/Action/Primary/Default.

The reason is what happens to a fill and its matching edge. Under the previous naming they were Action/Primary/Default and Border/Action/Primary/Default — describing one button's face and one button's edge, and not rhyming, because fills were special-cased to omit the property segment. Now they are parallel:

Background/Action/Primary/Default
Border/Action/Primary/Default

A state never appears mid-name. If a token you want seems to need one in the middle, you are reaching for the wrong token.

Two deliberate exceptions

Overlay stays top-levelTechnically every overlay is a background with alpha. It keeps its own group because it is the only alpha-carrying family in the system, and the group name is a useful warning that these composite rather than paint.
Brand/Logo is not semanticThree fixed asset colours describing one mark, not a role. Candidates to move out of the collection to the Logo page.

Code

CSS names are stored, not derived

Every variable carries an explicit WEB code-syntax string, and the Figma name and the CSS name deliberately differ. Background/ emits bg, because --color-background-action-primary-default is 41 characters and nobody wants that in a stylesheet.

Read variable.codeSyntax.WEB. Do not transform the name. This is also what settles the camelCase segments — OnSolid, OnStatus, OnNeutral, DangerSecondary — which used to be guessed at.

Icons

A glyph works out its own colour

An icon inside a button needs to be white on a primary, dark grey on a secondary, red on a danger and pale grey when disabled. The button cannot tell it that. The glyph sits two INSTANCE_SWAP levels down — button → sized wrapper → glyph — and nothing in that chain carries rank or state.

So the direction is inverted. Instead of the component reaching in to colour the icon, the icon asks what it is sitting in. Every glyph binds one variable, Icon/Current, and the component declares its context by setting a mode.

Mode on Icon contextResolves toSet it on
DefaultIcon/Regular#3E3E46Anything neutral. The fallback when no mode is set.
OnSolidIcon/OnSolid#FFFFFFPrimary and Danger fills, solid status grounds, checked controls.
DangerIcon/Status/Danger#B42419The danger low-emphasis ranks.
DisabledIcon/Disabled#B1B1BFAny disabled control.

State wins over rank — a disabled danger button sets Disabled, not Danger. A glyph placed with no mode set resolves to Default, so nothing ever renders invisibly.

Migrated203 vectors across Outline icons and Extra icons now bind Icon/Current instead of the gray-90 primitive.
Duotone still on a primitive90 vectors. A duotone glyph pairs a gray-90 primary with a brand-20 secondary; migrating only the primary would give a white-on-brand-20 glyph the first time anything set OnSolid. Needs Icon/Current Secondary first.
Icon/Placeholder is the exceptionThe one glyph token that must never take context. It is the "you have not swapped this yet" colour, and staying loud is its entire job.

States

One disabled rule, with one carve-out

Background/Action/Disabled+Border/Action/Disabled+Text/Disabled+Icon → Disabled

Ranks with no face at rest keep no face when disabled. Tertiary and DangerTertiary take Background/Action/Transparent and get no border. A ghost control that grows a grey box and an edge when you switch it off is louder disabled than enabled — its disabled state is carried entirely by the text and glyph colour.

On the ranks that do use it, Border/Action/Disabled is not decorative: Background/Action/Disabled alone is 1.15:1 against a white page, so the edge is the only thing keeping the control findable.

Text 22  ·  Icon 13

Icon's neutral rungs mirror Text's exactly — Strong, Regular, Subtle, Disabled, Inverse. The status values deliberately do not. A glyph carries less visual mass than a run of text at the same value, so status icons sit one to two steps more saturated. Mirroring Text 1:1 gives a near-black success tick and a brown warning triangle. Do not "fix" this.

FamilyTextIconWhy they differ
Infoblue-80blue-70One step lighter so the blue still reads as blue.
Successgreen-100green-80green-100 is effectively black at glyph weight.
Warningyellow-100yellow-90yellow-100 reads brown.
Dangerred-70red-70Red needs no correction at glyph scale.
Neutralgray-90gray-70A neutral dot should sit back; neutral text should not.

Text/Status/* goes on the Subtle tint; Text/OnStatus/* goes on the Solid fill. Crossing those two is the most common error this layer exists to prevent — and Text/OnStatus/Warning is dark, not white, because warning's solid is a light yellow.

Composites — build these, don't look them up

  1. Hover on a non-controlKeep the surface, composite Overlay/Hover on top. There is no Background/Raised/Hover and there should never be one — one wash works on every ground.
  2. Selected and hoveredBackground/Selected with Overlay/Hover over it. No third token.
  3. Focused and invalidBorder/Field/Error on the control, Border/Focus/Ring outside it. They stack; neither replaces the other.
  4. DisabledThe one rule above, every rank. Ranks with no face at rest keep no fill and no border.

Open decisions

  1. Border/Action/Secondary/Default is 2.12:1 on whiteBelow WCAG 1.4.11's 3:1 for non-text UI boundaries — and this edge is the only thing making a secondary button read as a button. Hover's gray-70 passes at 4.0:1. Darken the rest state to gray-60–70, or accept.
  2. Text/Disabled on Background/Action/Disabled is 1.85:1Disabled controls are WCAG-exempt, but this reads as broken rather than as disabled.
  3. DangerTertiary hover is red-10, a 2% washIt will not read as a hover. red-20 is the first visible tint; recommended hover red-20, pressed red-30.
  4. Background/Disabled vs Background/Action/DisabledSame value, and the same split exists on Border. A disabled surface and a disabled control genuinely differ, but the near-duplicate is the pattern that has produced orphaned bindings before. Confirm both are wanted.
  5. Brand/Logo/* in the semantic layerThree fixed asset colours that describe a mark, not a role. Move to the Logo page, or keep as a documented exception.
