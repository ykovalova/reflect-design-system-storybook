Naming

One rule, three segments, states always last

Group/Role/State
GroupWhat you're painting. Six, fixed: Surface, Action, Text, Icon, Border, Overlay.
RoleWhich slot. A neutral rung, a status family, or an action rank.
StateOptional, always last. Hover · Pressed · Selected · Disabled. Absent means rest.

Static and dynamic stop being a naming axis. They were doing two jobs on the board — separating cards from buttons, which is real, and separating rest text from label text, which isn't. The first job now belongs to a group boundary: Surface is what you paint a ground with, Action is what you paint an interactive control with. The second job disappears, because a state suffix already says it.

Keep static / dynamic / status as folders in the Figma panel if they help you browse. They just never appear in a variable name, because the same element changes class the moment someone makes it clickable.

The one new idea is the Overlay group. Translucent washes that composite over whatever is underneath. It's what lets a table row, a menu item, a clickable card and a ghost button all share one hover treatment instead of needing a hover token per surface — and it's the only way ghost controls survive being placed on a coloured banner.

Overlay groupScrim, hover and pressed washes, loading blanket. Unblocks modals, drawers, and every hoverable row.
Surface ladderFive neutral grounds instead of one. Unblocks cards, tables, panels, wells, tooltips.
Solid status fillsEvery family gains a filled weight and its on-fill foreground. Unblocks toasts, badges, dots, meters.
Selected as a statePromoted alongside hover and pressed. Unblocks tabs, nav, checkboxes, rows, options.

Group 1

Surface

Static grounds. Nothing here reacts to a pointer — interaction on a surface comes from an Overlay laid on top, which is why a clickable card doesn't need its own token set.

Group 5

Icon

Neutral rungs mirror Text exactly. Status does not — a glyph carries less visual mass than a run of text at the same value, so status icons sit one or two steps more saturated. Mirroring Text 1:1, as the board does, produces a near-black success tick and a brown warning triangle.

Before building

Six things only you can decide

  1. DangerGhost hover is very nearly invisible.Now that the steps are resolved: red-10 is #FDF9F9 — a 2% wash that will not read as a hover. red-20 (#F7E2E1) is the first visible tint on the red ramp. Recommend shifting the pair up one step: hover red-20, pressed red-30. This is the only value in the build I'd change on sight.
  2. Text and Icon are separate groups. Settled.The previous collection merged them as Text+icon/*; this structure splits them so status glyphs can sit more saturated than status text. Resolved on 2026-09-01 when the previous collection was deleted — the split is now the only structure in the file.
  3. Disabled text on a disabled fill lands around 2:1.gray-50 on gray-15. Disabled controls are exempt from WCAG, but this is faint enough to look broken. Either darken Text/Disabled to a gray-60 step, or lighten Surface/Disabled to gray-10.
  4. Do Ghost and Neutral want the same hover?Ghost hovers with a translucent wash; Neutral hovers with opaque gray-05. Side by side in a button group they will not match exactly. Making Neutral use the wash too would unify them — at the cost of a white button no longer having a fixed value.
  5. Does Page really move off white?Surface/Page → gray-05 is what makes cards read as raised without leaning on shadow alone. If the product is meant to be flat white, cards need a border instead and Surface/Raised becomes decorative.
  6. Status Solid for warning is a light fill.It's the only family whose on-fill text is dark. Worth confirming you want a light-yellow filled badge at all, rather than dropping warning's Solid weight and keeping it tint-only.

Drafted from the FigJam token tree, then built into branch qR9kXKS as the Semantic collection — 115 variables, every one aliased to a Primitive, scoped to its property, and carrying both its --color-* web code syntax and a usage description. The previous 88-variable semantic collection was deleted on 2026-09-01, so this is now the only semantic layer in the file. Two board nodes were low-resolution and read with lower confidence: the Background primary pressed step, and the text-versus-icon tertiary split.
